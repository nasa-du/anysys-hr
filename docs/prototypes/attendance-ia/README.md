# 考勤管理 · 信息架构与交互原型

低成本 HTML 原型，用于评审考勤管理的**信息架构（IA）与关键交互**。**不是生产代码**；数据保存在内存中，刷新即重置。

> **评审结论（2026-11-14）**：采用 **A · 模块独立**；排班工作台默认**方案视图（合并）**；考勤结果默认**全量日结果**（可一键切到异常优先）；无需再改，按当前原型定稿。B / C 保留在原型中作为参考，不进入实施方案。结论已记录在 ticket [#26](https://github.com/nasa-du/anysys-hr/issues/26) 的 resolution。

## 打开

直接双击 `index.html`，或用任意静态文件服务器打开。无需安装依赖。

- 默认方案 A，落地页为「排班工作台」。
- 底部悬浮条切换方案；键盘 `←` / `→` 也可切换（输入框内不拦截）。
- 「页面流程」查看当前方案的页面流程图。
- 「需求差异」查看与 `docs/requirement/rx-hr-prototype.html` 考勤面板的逐项对比。
- 「讨论问题」列出本次评审需要逐条回答的问题。
- 「状态」切换正常 / 加载中 / 空数据 / 错误，检查列表与详情的异常状态。
- 「窄屏」在桌面浏览器内模拟 430px 宽度；深色通过底部「深色」或 `?theme=dark`。
- 「重置」恢复初始数据（等同于刷新）。

URL 参数可直接分享：

```text
?variant=A|B|C
?page=schedule|import|results|rules|shifts|cockpit
?month=2026-09|2026-10
?theme=light|dark
?preview=normal|loading|empty|error
?narrow=1
?view=plan|employee&employee=E103
```

## 三个方案

三个方案共用同一套页面内容与样本数据，但**导航、页面拆分与主要操作路径不同**。

| | **A · 模块独立（采用）** | B · 单工作台 + 页签 | C · 异常优先驾驶舱 |
|---|---|---|---|
| 侧边栏 | 「考勤管理」分组下 5 个独立入口 | 单一「考勤管理」入口 | 单一「考勤」入口 |
| 页面拆分 | 排班工作台 / 导入中心 / 考勤结果 / 规则与节假日 / 班次 | 一个工作台，内部 4 个页签；班次用抽屉 | 驾驶舱 + 排班 / 导入 / 结果 / 规则四个模式 |
| 月份上下文 | 每页独立选择 | 页签间保持月份与公司 | 驾驶舱与模式间保持 |
| 视觉重心 | 每页一个任务 | 左轨道常驻月历与统计，右侧页签 | 异常收件箱 + 快捷操作 |
| 适合 | 把考勤当五个并列模块维护，深链接清晰 | 以「一个月」为单位连续工作：排班 → 导入 → 结果 → 月结 | 每天早上先看「今天要处理什么」 |
| 主要风险 | 来回切换页面会丢失月份/员工上下文 | 信息密度高，小屏更明显 | 排班入口较深，可能不适合排班密集的 HR |

### A · 模块独立

- 侧边栏：排班工作台、导入中心、考勤结果、规则与节假日、班次。
- 排班工作台：方案视图 / 员工明细视图；左方案列表 + 范围树，右月历。
- 导入中心：按数据类型分卡片；当前生效批次、预览批次、批次历史、导入规则与最近映射。
- 考勤结果：默认全量日结果（可一键切到异常优先）、员工月汇总、计算记录；顶部月状态与重算/确认/锁定/解锁/导出。
- 规则与节假日：公司默认规则、方案覆盖、节假日日历、修改影响面板。
- 班次：公司级班次模板 CRUD 与引用约束。
- 公司上下文在顶栏全局切换，与基础管理一致。

### B · 单工作台 + 页签

- 侧边栏只有一个「考勤管理」入口；进入后是「考勤工作台」。
- 顶部固定：公司、月份、月状态、页签（排班 / 导入 / 结果 / 规则）。
- 左侧常驻轨道：月历、本月统计、快捷操作（同步人员、复制下月、班次管理、导出）。
- 班次不占页签，从轨道或规则页打开抽屉。
- 适合评审「是否应该把考勤收成一个以月份为上下文的工作台」。

### C · 异常优先驾驶舱

- 默认落地是驾驶舱：月状态、5 个 KPI、异常收件箱、快捷操作、导入批次健康度、最近计算。
- 排班 / 导入 / 结果 / 规则以「模式」进入，顶部「返回驾驶舱」。
- 适合评审「HR 的主入口应该是待办/异常，而不是模块导航」。

## 建议评审路径

1. **A 排班工作台**：看 KPI、待同步横幅、冲突横幅；点击任意日期查看「这天谁上班」。
2. 切换「员工明细」，选周玉琼，看个人月历、双班日与 9-16 补休。
3. 点「批量填充」「复制下月」「同步人员」，检查预览与大小月提示。
4. **A 导入中心**：新建导入 → 载入样例 → 列映射 → 预览 → 提交；观察当前批次与历史变化。
5. **A 考勤结果**：默认全量日结果；勾选「只看异常」后打开胡国邵 9-7 旷工、李金辉 9-30 夜班、刘衍英 9-18 半天假，检查四方对照与时间轴。
6. 对任一异常做「人工调整」，填理由；查看版本历史；再「重新计算」。
7. 依次「确认」「锁定」「解锁」，检查状态时间线、解锁理由与快照。
8. **A 规则与节假日**：修改迟到宽限并保存，回到结果页看「结果已过期」；添加 / 删除节假日。
9. **A 班次**：新建班次；尝试停用被方案引用的早班，查看阻止原因。
10. 切换 **B / C**，重复 1–5 的关键步骤，比较导航、月份上下文与主入口差异。
11. 底部切「深色」「窄屏」「加载中 / 空数据 / 错误」，检查状态与可达性。
12. 打开「页面流程」「需求差异」「讨论问题」，逐条记录选择。

## 讨论问题

1. **整体导航**：A 五个独立入口 / B 单工作台 + 页签 / C 驾驶舱 + 模式？是否混合（例如 A 的侧边栏 + B 的月份上下文）？
2. **排班默认视图**：进入排班工作台时默认「方案视图」还是「员工明细」？是否需要并列双栏？
3. **排班编辑入口**：左侧方案列表 + 右侧月历，还是全屏日历 + 右侧抽屉？一天多班用弹窗还是侧栏编辑？
4. **导入向导**：独立导入中心，还是工作台页签？上传 / 粘贴 → 映射 → 预览 → 提交四步是否足够？错误报告放在预览内还是独立抽屉？
5. **结果页**：异常优先收件箱是否应作为默认？日详情抽屉宽度与四方对照信息量是否合适？月汇总放页签还是独立页？
6. **月结**：确认 / 锁定放结果页，还是独立月结页或驾驶舱？锁定前是否需要更明显的复核清单？
7. **规则 / 节假日 / 班次**：三者是一个设置页、三个页签，还是班次独立入口？方案覆盖如何在表单中表达「继承 vs 覆盖」？
8. **状态与可达性**：深色、窄屏、键盘与加载 / 空 / 错误是否满足？还缺哪些真实状态（例如导入解析中、重算进行中、并发提交冲突）？

## 与需求原型的差异

需求原型（`docs/requirement/rx-hr-prototype.html`）的「考勤管理」面板是一个纵向长页：班次表格、排班表、打卡文本域、OA 文本域、结果表格和「回填到工资计算」按钮依次排列。本原型在以下方面明确更好：

| 维度 | 需求原型 | 本原型 | 为什么更好 |
|---|---|---|---|
| 导航 | 单个长页面 + 顶部页签；考勤与薪酬混在同一面板 | A 五模块 / B 单工作台页签 / C 驾驶舱 + 模式 | 先把「按模块」还是「按月份」工作这件事交给评审选择 |
| 排班 | 排班表 + 月历；方案与明细混在一起 | 方案视图看模式，员工明细看个人月历；人工例外显式标记 | 分别回答「这天谁上班」与「这个人这个月怎么上」 |
| 批量操作 | 有填充 / 清空 / 复制，但没有影响预览 | 批量填充显示影响日期、覆盖员工、预计人日；复制下月提示大小月与例外 | 批量操作前先看到影响面，减少误覆盖 |
| 导入 | 内嵌文本域 + 「解析」「确认导入」 | 上传 / 粘贴 → 列映射 → 预览校验 → 提交；批次历史 + 覆盖影响 + 错误报告 | 把覆盖式刷新做成可审计的批次，而不是一次不可追溯的点击 |
| 结果 | 一张宽表 + 顶部按钮 | 全量日结果 + 可切换异常优先；日详情抽屉四方对照（排班 / 打卡 / OA / 结果）+ 时间轴 | 默认核对全量，异常可一键聚焦；差异原因一眼可见 |
| 人工调整 | 未体现 | 结果层调整表单；保留原值、调整值、理由、操作者；版本历史；重算后按日重新应用 | 调整可追溯，月结前可复核 |
| 月结 | 只有「回填到工资计算」 | 草稿 → 已计算 → 已确认 → 已锁定；解锁需理由；锁定生成快照 | 把「结果可用」与「结果不可变」分开，薪酬取数边界明确 |
| 规则 / 节假日 | 规则散落在多个输入区；没有独立节假日日历 | 公司默认 + 方案覆盖分组表单；节假日日历 + 修改影响提示 | 修改前知道影响哪些月份，避免静默改数 |
| 状态与可达性 | 基本只有正常路径 | 加载 / 空 / 错误状态；深色；窄屏；键盘与焦点样式 | 把异常状态当作一等公民 |

IA 层面的核心改进是：**排班、导入、结果不是一个长页里的三段表格，而是三个不同工作节奏的界面**。排班需要月历与范围树；导入需要可回退的批次向导；结果需要异常收件箱与四方对照。把它们塞进同一页会让每个任务都妥协。

## 样本数据

- **公司**：荣新矿业（完整样例）、荣新物流（空数据，用于检查公司上下文与空状态）。
- **员工**：`E101`–`E113`，与 `docs/specs/attendance-fixtures/README.md` 的员工种子一致。`E112` 已于 2026-08-31 离职；`E113` 2026-09-15 入职，初始标记为「待同步」。
- **班次**：行政班、技术员班、园林班、早班、中班、夜班（跨天）、凌晨班，取自 `docs/specs/attendance-golden-cases/base/shifts.json`。
- **排班方案**：全公司标准班、生产部早中班（周二 / 周四双班）、技术部技术员班、财务部行政班；另有人工例外 6 条，含一条时间重叠用于冲突预览。
- **节假日**：09-25 中秋节（来自黄金用例基础数据）；09-27 调休上班为原型示例，正式 2026 年安排以公司日历为准。
- **导入**：打卡 / 外出出差 / 加班单 / 请假补休的预览统计与错误列表来自 `docs/specs/attendance-fixtures/README.md`；原型不解析真实文件字节。
- **结果**：用简化的本地评估器从上述排班、打卡、OA 与规则生成，目的是让四方对照与月汇总自洽；**不是**黄金用例计算引擎，金额与分钟只用于界面演示。
- **2026-10**：初始为空，用于演示「复制下月」与目标月补排提示。

## 已知限制

- 刷新即重置；没有持久化、真实上传解析、鉴权或 RBAC。
- 结果评估器是界面演示用简化版；黄金用例仍以 `docs/specs/attendance-golden-cases/` 为准。
- 导入向导使用 fixture 统计模拟解析；提交后更新批次、覆盖影响与「结果过期」，但不重新解析真实文件。
- 方案只支持创建 / 编辑 / 复制 / 批量填充；归档、删除、方案版本历史未做成按钮。
- 节假日「复制上一年」只演示确认流程，不写入真实上一年数据。
- 班次只支持创建 / 编辑 / 停用；删除入口未暴露（引用规则已在提示中说明）。
- 只内置 2026-09 / 2026-10 两个月；更早/更晚月份不在原型范围。
- 弹层有初始焦点、Esc 关闭与 `aria-modal`，但未实现完整焦点陷阱；键盘可达性按「可评审」标准，而非 WCAG 全量审计。
