荣新员工管理与工资计算系统 · 整体设计方案

面向中小企业，基于《荣新工资计算逻辑.xlsx》中既定的薪酬结构与计算规则设计

模块清晰 公式可配置 Excel 批量导入 贴合中小企业

1设计目标与适用范围

目标：用一套轻量系统替代"每月手工维护一张大 Excel"的核算方式，做到：

  • 基础数据批量进：每月通过 Excel 模板导入员工信息、出勤、各项工资基数与加减扣项，一次导入、自动校验。
  • 工资字段公式化：工资列表中的每个字段（正常出勤工资、应发、社保、个税、实发等）都可由"公式"动态计算，业务人员可在界面上自定义/修改公式，无需改代码。
  • 规则沉淀为参数：最低工资标准、计薪天数、加班倍数、高温补贴、保密津贴等级、税率/社保费率等集中配置，调政策只改参数。

适用范围：单公司、或含多家公司的集团（公司与部门两级组织），数百人规模以内，标准月薪制为主、含综合工时/单休岗位的制造、矿业主导型企业。本方案不绑定具体语言与框架。

2系统总体架构与模块划分

模块清单

  1. M0 行政架构管理：公司 → 部门两级层级（树状）。部门归属某家公司，支持公司、部门的增删改查、岗位、汇报关系、成本中心、部门负责人。行政架构是驱动人员管理、岗位适用、权限与工资计算的主组织维度（成本架构见 M14）。
  2. M1 人员管理：员工全生命周期（新增 / 编辑 / 调岗 / 离职），按公司-部门组织，左侧部门树快速过滤，显式绑定所属岗位（岗位再装配薪酬构成、计算方案与工作日/考勤参数），并单独设置成本架构归属（仅用于支出统计与预警，见 M14），Excel 批量导入。
  3. M2 薪酬构成配置：维护可复用的薪酬构成（基本工资、高温补贴、加班费、保密津贴、社保/竞业补贴、合计等标准金额），按"薪酬包"维度设定，与计算方案、工作日参数解耦。
  4. M3 计算方案配置：维护可复用的计算方案（仅字段计算公式集），与薪酬构成、工作日参数解耦；当多个岗位"构成或工时不同但算法相同"时可共用同一计算方案，避免重复建方案。
  5. M4 工作日/考勤参数配置：维护可复用的工作日/考勤参数（月平均计薪天数、日工时、加班倍数、最低工资等），与薪酬构成、计算方案解耦；当多个岗位"构成或算法不同但工时相同"时可共用同一参数集。
  6. M5 岗位档案管理：岗位档案具公司属性，并分别绑定一套薪酬构成、一套计算方案与一套工作日/考勤参数，是"构成 + 计算方案 + 工作日参数"的装配点；员工绑定岗位即同时获得三者，无需按人设置薪酬方案。
  7. M6 月度数据导入：Excel 模板导入 + 字段映射 + 校验 + 预览。
  8. M7 考勤管理：班次定义（起止时间、跨天、午休段、休息扣除）→ 排班表（按月维护，支持同一天多班、按公司/部门/岗位/员工设定适用范围，可复制到下一月并自动处理大小月天数差异）→ 打卡明细导入（兼容钉钉考勤原始记录，自动过滤无效/重复卡）→ OA 申请导入（外出/出差、加班单、请假/补休，仅审批通过，与打卡就高融合）→ 考勤结果（出勤天数、迟到、早退、缺卡、旷工、事假/带薪假/补休、三类加班工时），一键回填工资计算。
  9. M8 公式计算引擎：字段公式解析、依赖求解、安全求值、重算；每套计算方案持有独立计算公式。

模块清单（续）

  1. M9 工资计算与核算：按月生成明细、触发重算、结果一致性校验。
  2. M10 工资列表与公式自助配置：展示每人每行各字段；并向最终用户开放字段与公式的增删改查（向导式界面，非仅管理员），按计算方案调整。
  3. M11 工资条与报表：个人工资条、部门汇总、导出 Excel/PDF。
  4. M12 权限与审计（轻量）：基于角色的访问控制（RBAC），所有变更留痕，敏感操作可审计。
  5. M13 账号与权限管理：系统用户的创建/编辑/删除/查询；通过角色为用户分配可访问的功能模块与可查看的部门数据范围，实现精确到部门的权限隔离（见 3.11/3.12 与 4.5）。
  6. M14 成本架构与工资支出统计：维护第二组织维度「成本架构」（公司 → 成本中心，含负责人、月度工资预算、预警线），人员在两套架构下分别归属；按成本中心归集当月工资支出（应发 / 社保 / 个税 / 实发，含下级汇总），与预算对比给出正常 / 接近预警 / 超预算三态并支持下钻人员明细——不影响任何既有计算与权限逻辑，为后续工资预警做铺垫（见 3.1.2）。
  7. M15 员工端 H5（考勤结果 / 工资条自助查询）：面向员工的独立移动端页面，提供考勤结果与工资条两个视图；采用发布制——管理端点击「发布」后才把当月核算结果做成只读快照推送至员工端，员工只能看到已发布快照，计算过程中的中间结果、未发布月份的数据一律不可见；支持撤销发布（撤销后员工端立即不可见）与发布包导出 / 导入（跨设备传递）。员工身份在真实环境中以企业微信 OAuth 身份绑定工号（原型以选择姓名演示），见 3.13。

3数据模型

下表为逻辑实体（与具体数据库无关）。带 * 的字段由公式/参数推导，非必须手工录入。

3.1 员工档案 employee（含组织归属与岗位引用）

字段说明来源
employee_id 工号唯一主键，导入匹配依据录入/导入
name 姓名 / gender 性别—导入
dept_id 所属部门关联 organization_department（含 company_id）——行政架构归属，驱动岗位适用、权限范围与工资计算等既有逻辑导入/组织架构带出
cost_org_id 成本归属关联 cost_organization（成本架构，见 3.1.2）——第二组织维度，与所属部门分别设置、可不同；仅用于工资支出统计与工资预警，不影响任何既有计算与权限逻辑录入/成本架构带出
position_id 岗位关联 position_arch（岗位档案），直接引用档案数据；岗位再装配"薪酬构成 + 计算方案 + 工作日/考勤参数"，人员只要选定岗位即同时获得三者（如 张三选定岗位"文员"，该岗位已关联行政类构成、标准工时方案与 7.5h 参数集）。不另设岗位文本字段，避免两处维护录入/岗位自动带出
manager_id 直属上级关联本表 employee_id，形成汇报线录入
status 在职状态在职 / 离职 / 试用期导入
hire_date 入职日期 / contract_type 合同类型全职/兼职/实习/劳务；用于司龄、试用期判断录入/导入
daily_hours 日工时 / monthly_rest 月休7.5 / 周休1 等（仅作人员档案备注，实际工时规则以方案工作日参数为准）导入
confidentiality_level 保密等级对应津贴档次（1~5）录入

3.1.0 公司 company（组织顶层）

字段说明
company_id 公司编号 / company_name 公司名称如 C1 荣新公司
parent_company_id 上级公司支持集团-子公司多级（可选）

公司是所有部门、人员与岗位档案的顶层归属。多公司场景下，岗位档案（含其薪酬构成/计算方案）、部门报表均按 company 隔离与汇总。

3.1.1 部门与岗位 organization_department（组织架构，归属公司）

组织架构是人员管理、岗位（含薪酬构成/计算方案）适用、报表汇总的基础骨架。以"公司 → 部门"两级为主、部门内部可再多级（中心/厂→部门→班组）；员工通过 dept_id 归属部门、通过 manager_id 形成汇报线。

字段说明
dept_id 部门编号 / dept_name 部门名称如 D1 行政部、D2 生产部
company_id 所属公司关联 company；每个部门必归属一家公司，构建"公司-部门"层级
parent_id 上级部门自引用，构成部门层级；顶层为 NULL
manager_id 部门负责人关联 employee.employee_id
cost_center 成本中心编码用于费用归集与部门报表
positions 岗位清单该部门下设岗位（如 文员 / 班长 / 财务）
order_no 排序同层级展示顺序
与岗位、核算的关系：员工通过 position_id 关联 position_arch（岗位档案），岗位档案已绑定所属公司与"薪酬构成 + 计算方案"；员工入职时归属部门与岗位即自动获得对应的薪酬配置，无需逐人/逐方案配置；部门汇总报表（M11）也基于"公司-部门"层级聚合。

3.1.2 成本架构 cost_organization（第二组织维度：公司 → 成本中心）

成本架构是与行政架构并行维护、彼此独立的第二套组织维度：行政架构回答"人归哪个部门、怎么算工资"，成本架构回答"工资支出统计到哪个成本中心"。它不驱动岗位适用、权限范围、工资计算等任何既有逻辑，只承载成本归属 + 月度工资预算 + 预警线，用于从另一维度统计整个部门 / 成本中心的工资支出，并为后续工资预警做铺垫。

字段说明
cost_org_id 成本中心编号 / cost_org_name 名称如 CO-PROD 生产成本中心、CO-LOG 物流成本中心
company_id 所属公司关联 company；与行政架构共用公司顶层
parent_id 上级成本中心自引用，构成成本层级；顶层为 NULL。统计时含下级汇总
manager_id 负责人关联 employee.employee_id
budget 月度工资预算该成本中心当月工资支出预算（0 = 不设预算，不参与预警）
warn_pct 预警线（%）预算执行率达到该比例即进入"接近预警"状态（默认 85%）
order_no 排序 / note 备注同层级展示顺序；成本归集范围说明
双归属与解耦：人员在「人员管理」中分别设置行政归属（dept_id）与成本归属（cost_org_id）——例如黄国锋行政归属生产部-皓程车间（D9）、成本归属皓程车间成本中心（CO-PROD-1），两者可不同。工资支出统计（M14）按成本架构归集应发 / 社保 / 个税 / 实发，与预算对比给出正常 / 接近预警 / 超预算三态，并支持下钻到人员明细；统计范围同样服从 RBAC 人员可见范围。工资预警可在该预算与预警线基础上扩展（阈值调整、超支通知、趋势对比）。

3.2 薪酬构成 compensation_composition（可复用构件，与计算方案解耦）

薪酬构成即"薪酬包各项标准金额"：基本工资、高温补贴、加班费、保密津贴、社保/竞业补贴、合计等，按"薪酬包"维度一次性设定。它与计算方案彼此独立、分别复用——同一套构成可被多个岗位引用，同一套计算方案也可被多个（构成不同的）岗位共用。仅当调薪/结构调整时调整并生成新版本。

字段含义说明
comp_id 构成编号 / comp_name 构成名称如"行政类薪酬构成""生产类薪酬构成"可复用主键与展示名
base_salary 基本工资标准正常工作时间工资构成级标准
hightemp_subsidy 高温补贴标准300/150/0按岗位+季节参数
performance_salary 绩效工资标准—构成级 或 *派生=合计−其他
overtime_pay 加班费标准月度包内加班报酬构成级
confidentiality_allowance 保密津贴标准按等级 5000/2000/1000/500/240按等级参数
social_subsidy / noncompete_subsidy社保/竞业补贴构成级
total_package 工资金额合计= 基本+高温+绩效+加班+保密+社保+竞业*校验
version 版本号 / status 状态生效·停用变更时新建版本，旧版保留以便追溯

3.3 计算方案 calc_scheme（可复用构件，与薪酬构成、工作日参数解耦）

计算方案仅承载字段计算公式集，不绑定任何金额，也不含工作日参数（工作日参数已独立为 3.4）。因此可被"构成或工时不同、但算法相同"的多个岗位共用——这正是解耦带来的收益：无需为每个岗位各建一套"含金额 + 含参数 + 含公式"的完整方案。每套计算方案可定义独立计算公式（见 3.9）。

字段含义说明
calc_id 方案编号 / calc_name 方案名称如"通用计算方案（统一公式集）"可复用主键与展示名
formulas 计算公式集字段键→公式表达式每套计算方案独立（见 3.9）；工作日参数见 3.4
解耦示意：行政类岗位（7.5h）与财务类岗位（7.5h）工时相同 → 共用同一"工作日/考勤参数"；二者"薪酬构成"不同（高温/保密津贴等金额不同）则各自绑定不同的薪酬构成；而三者的计算公式完全相同 → 共用同一"计算方案"。最终只需 1 套计算方案 + N 套薪酬构成 + M 套工作日参数，而非 N 套"金额+参数+公式"全量方案。

3.4 工作日/考勤参数 workday_param（独立可复用构件，与薪酬构成、计算方案解耦）

工作日/考勤参数即工时与考勤相关参数：月平均计薪天数、日工作小时、加班倍数、当地最低工资等。它不含任何金额、也不含公式，因此可被"构成或算法不同、但工时相同"的多个岗位共用——如行政类(7.5h)与财务类(7.5h)共用一套参数，生产类(8h)用另一套。每套参数可被多个岗位绑定（见 3.5）。

字段含义说明
workday_id 参数集编号 / workday_name 名称如"标准工时（7.5h）""生产工时（8h）"可复用主键与展示名
avg_pay_days 月平均计薪天数21.75国家规定
work_hours 日工作小时生产类 8 / 行政类 7.5用于加班折算，区分工时差异
ot_mult_weekday / weekend / holiday1.5 / 2 / 3延时/休息日/法定节假日加班倍数
min_wage 当地最低工资2040（肇庆 2026-09 起）地区/生效期
与计算方案解耦：计算方案（3.3）只管"怎么算"（公式），工作日参数（本节点）只管"按什么工时/倍数算"（参数），薪酬构成（3.2）只管"金额多少"。三者通过岗位（3.5）自由组合装配，互不牵制。

3.5 岗位档案 position_arch（公司属性 + 装配点）

岗位档案是"薪酬构成 + 计算方案 + 工作日/考勤参数"的装配点，且具公司属性（每个岗位必归属一家公司）。员工绑定岗位后，即同时获得该岗位的三项配置，无需按人设置薪酬方案。

字段含义说明
position_id 岗位编号 / position_name 岗位名称如 文员 / 班长 / 财务岗位主键与展示名
company_id 所属公司关联 company岗位归属公司，构建"公司→岗位"归属
comp_id 绑定薪酬构成关联 3.2 compensation_composition岗位的各项标准金额来源
calc_id 绑定计算方案关联 3.3 calc_scheme岗位的字段公式来源
workday_id 绑定工作日/考勤参数关联 3.4 workday_param岗位的工时与加班倍数来源
dept_id 默认部门（可选）关联 organization_department便于人员建档时带出部门
order_no 排序展示顺序—
与月度核算的关系：薪酬项标准、工作日参数与字段公式由"员工→岗位→构成/计算方案/工作日参数"自动带出，只在岗位装配时设定一次；每月核算时系统按员工所属岗位自动取用，月度 Excel 导入仅承载出勤 / 加班小时 / 加减扣项等当月变动数据，彻底避免重复导入与逐月/逐人维护。

3.6 参数分层管理

参数分为两层：考勤/工作日参数已独立为「工作日/考勤参数」构件（见 3.4），由岗位单独绑定以区分生产类与行政类工时；法定口径参数仍全局统一，避免口径分裂。

参数层参数默认值说明
全局统一（法定）tax_threshold 个税起征点 / tax_rate 税率5000 / 0.03全公司一致
social_rate 社保费率0.23338按基本工资计
confidentiality_tier 保密津贴档5 档（见政策）按等级
方案级（考勤/工作日）min_wage / avg_pay_days / work_hours2040 / 21.75 / 8(或7.5)随方案差异化
ot_mult_weekday / weekend / holiday1.5 / 2 / 3延时/休息日/节假日
hightemp_tier 高温标准户外300 / 室内150 / 0按岗位+月份

分组字段
出勤weekday_full 工作日满勤、weekend_full 周末满勤、weekday_attended 工作日出勤、weekend_attended 周末出勤、paid_leave_days 带薪天数

3.8 考勤管理 attendance（班次 → 排班表 → 打卡明细 → 考勤结果）

3.8.4 考勤计算规则与结果

规则默认值含义
punch_window_min 上班卡可提前打卡120 分钟上班卡归属窗口下界 = 排班开始 − 该值
late_cap_min 上班卡最晚归属240 分钟超过则该打卡不再算作本班上班卡
early_cap_min 下班卡最早归属240 分钟早于排班结束该时长内的打卡，仍算作本班下班卡
ot_max_min 加班时长上限600 分钟当日最后一班结束后最多计入加班的时长；同时受「下一班上班时间」约束
late_grace_min / early_grace_min 迟到/早退宽限5 分钟超过宽限才计迟到/早退
ot_threshold_min 加班起算时长30 分钟单班加班不足该分钟数不计
absent_if_no_punch 无打卡计旷工是排班日完全无打卡计旷工，否则计缺卡
打卡归属与加班判定（核心规则）：
  1. 上班卡取该班窗口内最早的打卡；下班卡取窗口内最晚的打卡。
  2. 非当日最后一班：下班卡窗口严格到排班结束时刻。排班结束之后、下一班上班之前的打卡，按业务规则视为「下班打卡」——既不计入本班工时，也不计为加班，避免把班间休息误算成加班。
  3. 当日最后一班：下班卡窗口延伸至 min(排班结束 + 加班上限, 下一班上班时间 − 上班卡可提前时长 − 1)。
    这样既能正确认领次日凌晨的跨天下班卡（计入当日加班），又不会把次日正常的早到卡吞掉。
  4. 加班 = 下班卡 − 排班结束，超过起算时长才计入；按当日类型拆分为延时 / 周末 / 节假日三类（节假日清单可维护）。
  5. 迟到 / 早退按各自宽限判定；缺卡指有上班卡无下班卡（或反之）；旷工指排班日完全无打卡。
  6. 一键回填：考勤结果写回月度导入——出勤天数（拆分工作日 / 周末）、三类加班工时、考勤扣款（负数表示扣减，如旷工×100、迟到×20，扣款规则可配置），工资引擎按月度导入值取用。

3.8.5 OA 申请数据（外出/出差 · 加班单 · 请假/补休）

OA 审批通过的申请是考勤计算的第二数据源（与打卡明细互补）：打卡反映"实际发生了什么"，OA 申请反映"组织批准了什么"，二者按下列规则融合。员工标识为姓名，与员工档案匹配；出差人一行的多人按分隔符拆分为多条。

OA 表单关键列（按列名映射，多余列忽略）目标实体纳入条件与口径
外出、出差申请出差人 / 申请类型 / 开始时间 / 结束时间 / 出差天数 / 外出事由 / 审批结果 / 审批状态oa_trip审批结果=审批通过；覆盖排班日计出勤；一行多人拆分
加班单创建人 / 部门 / 加班开始时间 / 加班结束时间 / 加班时长（天/小时）/ 加班原因 / 审批结果 / 审批状态oa_overtime审批结果=审批通过；时长按起止时间计算（手工填报值仅作参考），单日 8 小时封顶、跨天按日拆分
请假、补休、假单取消申请创建人 / 请假类型 / 请假天数 / 休息开始时间 / 休息结束时间 / 上班开始时间 / 上班结束时间 / 结余补休天数 / 审批结果 / 审批状态oa_leave审批结果=审批通过；类型分 事假 / 带薪假 / 补休调休；「上班开始时间」指向被补休的加班日
OA 与打卡的融合规则：
  1. 外出/出差（审批通过）覆盖的排班日计出勤——当日无打卡也计；有打卡时按打卡计算工时，OA 仅作标注，外出本身不计加班。
  2. 加班单（审批通过）：当日加班工时取「打卡计算值」与「OA 审批值」的较大者（就高不就低，避免漏打卡少算加班）；休息日（未排班）的审批加班单直接计入周末/节假日加班。
  3. 请假（审批通过）：事假不计出勤（也不计旷工）；带薪假不计出勤但计入带薪假天数，回填后走带薪假工资公式；多日请假按覆盖排班日折算每日天数。
  4. 补休/调休（审批通过）：休息日不计出勤；同时按「补休天数 × 8 小时」抵扣被补休加班日（上班开始时间对应日期）的加班工时，抵扣量在明细与汇总中单独列示。
  5. 过滤规则：仅「审批通过」计入；审批中 / 终止 / 审批未通过按类计数跳过；姓名不在员工档案的跳过并提示；重新导入为覆盖式刷新。

后续可通过钉钉开放接口（审批单据查询、考勤原始记录推送）自动采集替代手工粘贴，字段映射与融合规则不变。

3.9 字段公式定义（全系统统一字段名 + 每计算方案独立公式）

工资列表字段与"全系统统一"：字段名称、类别、来源、显隐与顺序在所有方案中保持一致（一份全局字段定义）；而计算公式每套计算方案可独立定义（见 3.3 的 formulas）。配置表向最终用户开放（不仅限管理员）：业务/财务人员可在界面上自行对字段与公式做增、删、改、查，无需提需求改代码。

层面内容说明

面向最终用户的配置能力（增删改查）：
  • 增：新增自定义字段（如"司龄补贴""夜班津贴"），选择类别与数据来源，写入公式即生效，自动进入工资列表与核算。
  • 删：停用 / 隐藏不再使用的字段（软删除，保留历史结果可追溯），不影响已出工资。
  • 改：可视化编辑公式——字段选择器 + 函数面板 + 参数下拉 + 实时试算；保存前自动校验语法与依赖环。
  • 查：字段与公式一览视图，支持按类别筛选、变更历史查看；非管理员在授权范围内即可操作，向导式引导降低门槛。

3.12 角色 sys_role（功能权限 + 部门数据可见范围）

角色是权限的载体，包含两个维度的授权：①可访问的功能模块；②可查看的部门数据范围。为用户分配角色即获得对应权限；修改角色即时影响所有拥有该角色的用户。

字段说明
role_id / role_name 角色名如 系统管理员、人事专员、生产薪资专员、财务查看
desc 描述角色职责说明
module_keys 功能模块集合如 ['org','personnel','payroll','import']；决定该角色能进入哪些功能页签
dept_scope 部门可见范围{type:'all'} 表示全部部门；{type:'list', depts:[部门ID…]} 表示仅指定部门（含其下级部门，按部门树自动展开）
权限生效逻辑（RBAC）：
  • 功能权限：用户任一角色包含某模块即有权访问该页签；无权限的页签直接隐藏。
  • 数据权限：取该用户所有角色可见部门的并集（任一角色为"全部"则开放全部）；人员管理、工资列表、工资导入均以此范围为底座，仅展示/导入授权部门内的员工，越权数据不可见。
  • 导入校验：月度工资导入时，若某行员工不在当前用户可见部门内，直接报"无权导入"并拦截，确保数据边界不被突破。

3.13 员工端发布 publish_snapshot（H5 移动门户的数据来源）

员工端 H5（M15）不直连计算库，只读取「发布快照」。管理端在考勤结果与工资计算定稿后点击「发布」，系统按当前月份生成快照并写入发布存储（原型为浏览器 localStorage，正式环境为服务端发布表 + 消息推送）。

快照内容说明
考勤快照月份、发布时间、人数；每人：月度汇总（排班/出勤/旷工/迟到/早退/缺卡/事假/带薪假/补休/外出/三类加班/OA 审批加班/补休抵扣）+ 每日班次明细（日期、类型、班次、计划时间、上下班卡、工时、加班、状态、备注）
工资条快照月份、发布时间、人数；每人：按该员工所属计算方案的字段分组明细（名称 + 数值）+ 应发 / 社保 / 个税 / 实发四项合计
发布元数据published_at 发布时间、count 覆盖人数；重新发布为覆盖式刷新；撤销发布后员工端立即不可见
发布制的目的——避免中间结果外泄：
  • 考勤与工资在管理端可持续调整（改排班、导打卡、改公式、试算），员工端始终只呈现已发布的那一版，调整过程中的中间数字不会泄漏给员工。
  • 发布动作可限定在「定稿后」由人事/薪资专员执行；撤销发布提供纠错通道（发错月份、算错可先撤再改再发）。
  • 原型以同一浏览器的 localStorage 演示「发布即可见、撤销即消失」；正式环境建议以企业微信应用消息推送「工资条已发布」通知，员工点击进入 H5（身份取企微 OAuth 绑定的工号），并可扩展历史月份归档查询。

4公式计算引擎处理逻辑

引擎是系统"公式可自定义"能力的核心。每个工资列表字段在 salary_field_def 中拥有一行定义；引擎把"导入值 + 参数 + 其他字段值"作为作用域，对公式表达式求值。

4.1 处理流程

① 取数按员工→所属岗位→岗位绑定的计算方案，组装作用域（岗位薪酬构成 + 计算方案工作日参数 + 月度导入值 + 考勤结果）；考勤结果由"打卡明细 × 排班表"与"OA 审批申请（外出/出差、加班单、请假/补休）"融合计算得出（出勤天数、三类加班工时等，见 3.8）
② 解析取该员工所属计算方案的字段公式，编译为 AST
③ 建图提取字段引用，构建依赖图
④ 排序拓扑排序得到求值顺序，检测环
⑤ 求值按序逐个字段代入计算（参数优先取计算方案工作日参数，再取全局法定参数）
⑥ 校验一致性校验，写回结果表

4.2 公式语法（类 Excel，业务人员易上手）

  • 字段引用：直接用字段键，如 base_pay、overtime_pay。
  • 参数引用：用花括号，如 {avg_pay_days}、{work_hours}、{ot_mult_weekday}、{min_wage}、{social_rate}（工作日参数取方案级、法定参数取全局）。
  • 运算符：+ - * / ( )，支持比较与 IF(cond,a,b)。
  • 内置函数（白名单）：ROUND、SUM、MIN、MAX、ABS、IF。

4.3 默认公式清单（自 Excel 逻辑沉淀，可在界面修改）

字段（键）默认公式（按 Excel 列）含义
base_pay 基本工资(实) S= base_salary / weekday_full * weekday_attended按工作日出勤比例折算
hightemp 高温(实) T= hightemp_subsidy固定
performance 绩效(实) U= ROUND( performance_salary - total_package/(weekday_full+weekend_full)*((weekday_full+weekend_full)-weekday_attended-weekend_attended) + (base_salary-base_pay) + (overtime_pay-overtime_pay_actual), 2)含缺勤扣减+基本/加班差补
overtime_pay_actual 加班费(实) V= overtime_pay / weekend_full * weekend_attended按周末出勤比例折算
confidential 保密(实) W= confidentiality_allowance固定
social_sub / noncompete_sub X/Y= social_subsidy / = noncompete_subsidy固定
normal_pay 正常出勤工资 Z= ROUND( base_pay+hightemp+performance+overtime_pay_actual+confidential+social_sub+noncompete_sub, 2)各项实发之和
paid_leave_pay 带薪假工资 AE= ROUND( base_salary/{avg_pay_days} * paid_leave_days, 2 )带薪假折算（引用方案基本工资与计薪天数，基数参数化）
ot_subsidy 加班补贴 AF= ROUND( base_salary/{avg_pay_days}/{work_hours}*{ot_mult_weekday}*ot_weekday + base_salary/{avg_pay_days}/{work_hours}*{ot_mult_weekend}*ot_weekend + base_salary/{avg_pay_days}/{work_hours}*{ot_mult_holiday}*ot_holiday, 2)三类加班按方案日工时与倍数分别计算
addon_sum 加减项小计 AN= ROUND( SUM(带薪假,加班补贴,话费,车补,其他,生产奖,提成…), 2)加项−减项小计
gross 应发工资 AO= ROUND( normal_pay + addon_sum, 2)应发
tax 本期个税 AQ用户自定义（如累进税公式 / 对接测算）可配置
social_this 本期社保 AP用户自定义（如基数×费率）可配置
deduct_sum 扣减项小计 AS= SUM(social_this, tax, paid_advance)扣减合计
net 实发工资 AT= ROUND( gross + deduct_sum, 2)实发（扣减为负）
数据质量提示（来自源文件）：原 Excel 中"带薪假工资 AE""加班补贴 AF"使用硬编码基数 1850（如 1850/21.75），未与基本工资/正常工作时间工资联动。设计中已改为引用计算方案级字段与工作日参数（如 base_salary / {avg_pay_days} / {work_hours} / {ot_mult_weekday}），基数随计算方案基本工资与计薪参数自动联动，避免政策调整时漏改。

4.4 安全与可靠性

  • 沙箱求值：仅允许白名单函数与运算符，禁止文件/网络/系统调用；设单表达式超时与最大递归深度。
  • 依赖管理：自动解析字段引用生成依赖图；出现循环引用立即报错并定位字段。
  • 重算触发：导入新数据、修改参数、修改任一字段公式时，自动标记相关月份为"待重算"并支持一键全量重算。
  • 一致性校验：强校验 normal_pay = Σ各项实发、gross = normal_pay + addon_sum、net = gross + deduct_sum；缺项/类型错误给出明细提示。
  • 可追溯：结果表记录计算时间与数据批次，公式修改留审计日志。

4.5 权限控制（RBAC）与计算/展示的关系

公式计算引擎本身对每个员工一视同仁；权限控制在"入口"与"出口"两端生效，不改变计算逻辑，只控制"谁能看、谁能导"：

登录校验账号与状态，载入其角色集合
页签过滤仅显示角色授权的功能模块
部门范围取角色可见部门并集（含下级）
数据底座人员管理/工资列表只取授权部门员工
导入校验越权部门员工行直接拦截报错

示例：角色"生产薪资专员"仅含模块 [人员管理, 工资列表, 月度导入] 且部门范围限定"生产部"，则该用户登录后看不到组织架构/薪酬构成/计算方案/岗位档案/账号管理等页签，人员与工资列表只显示生产部员工，尝试导入其他部门员工的工资会被拦截。角色"系统管理员"模块为全部、部门范围为全部，拥有完整权限。

6关键业务规则与参数（源自 Excel 政策文本）

  • 正常工作时间工资底线：肇庆市 2026-09 起 2040 元/月，合同更高的以合同为准；参数随政策调整。
  • 加班基数：以正常工作时间工资为基数；延时×1.5、休息日×2、法定节假日×3，均 ÷21.75÷8。
  • 高温补贴：户外露天 300、室内非露天高温 150、非高温 0（按岗位+规定月份发放）。
  • 保密津贴（5 档）：高层 5000、中层 2000、集团总部基层 1000、下属公司基层及关键涉密岗 500、班长及一般涉密基层 240。
  • 计薪天数 21.75、日工时 现为计算方案级参数（生产类 8、行政类 7.5），以区分工时差异；法定个税/社保口径仍为全局。
  • 单休/综合工时：月度工资包已含固定出勤下的加班报酬，实际出勤不足时按公式扣减（见 performance 公式）。

7中小企业落地建议与下一步

  • 分阶段：先上 M0~M6（搭好公司-部门组织、人员与岗位绑定、月度导入，导入即出工资结果），再上 M7 考勤管理（班次定义 → 排班表 → 打卡明细与 OA 申请导入 → 考勤结果一键回填），M8~M11（公式引擎/工资核算/公式自助/工资条报表）、M12（权限审计）与 M13（账号与角色管理，RBAC 精确授权）随后。
  • 模板化：把当前 Excel 整理为"导入模板"与"结果导出模板"两份，降低一线人员学习成本。
  • 方案化治理（最终用户自助）：薪酬构成按"构成"统一设定、计算方案按"方案"独立持有公式，工作日/考勤参数独立为参数构件，三者解耦、由岗位档案装配，均不再按人逐条配置；个税/社保等易变项与各计算方案的独立公式由业务/财务人员在字段公式配置界面按计算方案自行增删改查（向导式+实时试算），无需管理员改代码；法定参数仍全局统一，考勤结果由 M7 自动计算回填。
  • 数据口径：修正 1850 硬编码基数问题；统一以"工号/部门编号/公司编号"为主键，规避重名与归属歧义。
  • 双组织架构与工资预警：行政架构（M0）与成本架构（M14）并行维护、人员分别归属；成本架构不影响计算与权限，仅从另一维度归集工资支出（应发/社保/个税/实发，含下级汇总）并与月度预算对比输出预警三态——建议先行按"生产成本 / 物流 / 项目 / 职能"设定成本中心与预算试运行一个季度，校准预算口径后扩展工资预警（超支提醒、环比趋势、人均成本分析）。
  • 员工端 H5 上线（M15）：考勤与工资定稿后由人事/薪资专员点击「发布」生成只读快照，员工经企业微信进入 H5 查看考勤结果与工资条；上线初期建议与现有「工资条纸质/邮件发放」并行一个月，确认员工自助查询稳定后再切换为主通道。历史月份归档、订阅提醒（发布通知）可在稳定运行后扩展。

本方案为系统整体设计，未涉及编程语言/框架选型；后续可基于此模型与引擎逻辑进入原型搭建。
