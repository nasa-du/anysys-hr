# 薪资管理 · 信息架构与交互原型

低成本 HTML 原型，用于评审薪资管理的**信息架构（IA）与关键交互**。**不是生产代码**；数据保存在内存中，刷新即重置。原型覆盖：薪资独立模块入口、配置与月度工作的节奏分离、公式编辑器、月度导入预览、工资列表与明细、薪资月生命周期、工资条与批量导出、成本统计与预算预警，以及异常状态。

> **评审结论（2026-11-28）**：采用 **A · 双区模块独立**（薪资月度 5 个入口 + 薪资配置 6 个入口）。保留以下结构决定：配置六类独立、核算与确认独立成页、正式/预览工资条分离 + 异步导出、成本统计独立报表。B / C 保留在原型中作为参考，不进入实施方案。
>
> 评审期间修正：公式编辑器编辑区显示中文名、保存时转换为 ASCII 键；全局参数支持新增（数值参数进入公式面板）；术语统一为「薪资」。结论已记录在 ticket [#52](https://github.com/nasa-du/anysys-hr/issues/52) 的 resolution。

- 关联决议：ADR-0006～0011、`GLOSSARY.md`、`docs/specs/payroll-golden-cases/`

## 打开

直接双击 `index.html`，或用任意静态文件服务器打开。无需安装依赖。

```bash
cd docs/prototypes/payroll-ia
python3 -m http.server 8765
# http://127.0.0.1:8765/index.html
```

- 默认方案 A，落地页为「工资列表」；方案 C 的落地页为「薪资驾驶舱」。
- 底部悬浮条切换方案；键盘 `←` / `→` 也可切换（输入框 / 文本域 / 下拉内不拦截）。
- 「页面流程」查看当前方案的页面流程图；「需求差异」查看与需求原型的逐项对比；「讨论问题」列出本次评审要逐条回答的问题。
- 「状态」切换正常 / 加载中 / 空数据 / 错误，检查列表、详情与整页异常状态。
- 「窄屏」在桌面浏览器内模拟 430px 宽度；深色通过底部「深色」或 `?theme=dark`。
- 「重置」恢复初始数据（等同于刷新）。

## 三个方案

三个方案共用同一套页面内容与样本数据，但**导航、月度上下文与主入口不同**。

| | **A · 双区模块独立** | B · 月份工作台 + 配置中心 | C · 任务驾驶舱 + 模式 |
|---|---|---|---|
| 侧边栏 | 「薪资月度」5 个入口 + 「薪资配置」6 个入口 | 两个入口：薪资月度工作台 / 薪资配置中心 | 驾驶舱 + 本月工作 5 个模式 + 配置中心 |
| 配置 / 月度 | 两组独立页面，配置页无月份上下文 | 工作台页签承载月度；配置中心页签承载 6 类配置 | 月度以模式进入，配置中心内部左侧分区 |
| 月份上下文 | 每页独立月份条；URL 保持月份 | 顶部常驻月份 ribbon + 4 步 stepper | 驾驶舱月份条；模式内紧凑月份条 |
| 视觉重心 | 每页一个任务；配置与月度节奏清楚 | 以「一个月」为单位连续工作，页面密度高 | 先看「本月要处理什么」，再进入模式 |
| 适合 | 把薪资当独立模块维护，深链接清晰；配置变更与月度操作不互相打断 | HR 按月连续作业：导入 → 核算 → 确认 → 发工资条 | 每天先看状态、待办、异常与预算预警 |
| 主要风险 | 页面间切换可能丢失月份 / 员工上下文 | 工作台信息密度高，小屏更明显 | 月度入口较深；配置入口藏在侧边栏 |

### A · 双区模块独立

- 侧边栏：薪资月度（工资列表、月度导入、核算与确认、工资条、成本统计）；薪资配置（薪资构成、计算方案、工作日参数、岗位装配、字段与公式、全局参数）。
- 月度页顶部统一月份条：月份、状态、输入版本、最近成功批次、考勤锁定、待重算 / 考勤过期 / 范围变化 / 配置已更新 / 最近批次失败徽标，以及导入 / 重算 / 确认 / 发工资条 / 解锁动作。
- 配置页顶部说明配置影响：修改后当前月标记「配置已更新」，历史月沿用快照。
- 适合评审「配置与月度是否应该彻底分成两组入口」。

### B · 月份工作台 + 配置中心

- 侧边栏只有「薪资月度工作台」与「薪资配置中心」。
- 工作台顶部常驻月份 ribbon：月份切换、状态徽标、四步 stepper（月度导入 → 核算 → 确认 → 发工资条）、主操作；页签：工资列表 / 月度导入 / 核算与确认 / 工资条 / 成本统计。
- 配置中心顶部展示配置健康（构成 / 方案 / 工作日 / 字段 / 全局参数 / 未装配岗位），页签切换 6 类配置。
- 适合评审「是否应该把薪资收成一个以月份为上下文的工作台」。

### C · 任务驾驶舱 + 模式

- 默认落地是薪资驾驶舱：KPI（在册 / 应发 / 实发 / 预算执行率 / 成本预警）、本月待办（导入 / 考勤 / 装配 / 核算 / 确认 / 工资条 / 导出）、异常与提醒、快捷操作、最近核算、配置健康。
- 工资列表 / 导入 / 核算 / 工资条 / 成本以「模式」进入，顶部保留「返回驾驶舱」；配置中心从侧边栏进入，内部左侧配置分区。
- 适合评审「HR 的主入口应该是待办 / 异常，而不是模块导航」。

## 建议评审路径

1. **A 工资列表**：看 KPI、月份状态条、动态列、合计行；点击 E101 打开明细抽屉，核对来源、公式、考勤来源、配置快照与一致性校验。
2. 用部门 / 岗位 / 成本中心 / 未分配 / 关键词筛选；打开「列设置」增删列；导出明细 CSV。
3. **A 月度导入**：看考勤来源只读卡片与当前生效批次；新建导入 → 载入示例文件 → 列映射（注意考勤列标记为「忽略」）→ 预览校验（未知员工、重复行、姓名不一致、缺失清零、覆盖手工值）→ 仅保留有效行 → 提交；观察输入版本与「待重算」。
4. **A 核算与确认**：看核算前检查与批次历史；打开失败批次 `R-2611-01`；点击「模拟考勤解锁」看阻断与待重算；恢复后重新核算；确认 → 发工资条；解锁需理由。
5. **A 工资条**：预览工资条与正式工资条（切到 2026-10 已发月）；批量导出三种格式；创建任务观察进度与有效期；下载过期产物检查 410 提示。
6. **A 成本统计**：看公司合计、四个成本中心的三态预算、未分配行；点击「生产成本中心」下钻；在工资列表中按成本中心筛选。
7. **A 配置区**：新建薪资构成（合计随明细实时汇总）；新建计算方案；配置 OP 方案的公式（插入字段 / 函数 / 参数，试算，制造循环引用看错误）；新建工作日参数；装配「司机」岗位；新增字段；编辑全局参数。
8. **B**：在月份工作台走完 导入 → 核算 → 确认 → 工资条；观察顶部月份 ribbon 与 stepper 是否让月份上下文更清楚；到配置中心横向比较六类配置。
9. **C**：从驾驶舱的待办与异常进入导入 / 核算 / 工资条 / 成本；返回驾驶舱看 KPI 与待办变化；到 2026-12 看未锁定月与未装配岗位；从侧边栏进入配置中心。
10. 切换 2026-12 检查草稿 / 未锁定 / 未装配 / 无结果；切换荣新物流检查公司空状态。
11. 底部切「深色」「窄屏」「加载中 / 空数据 / 错误」，检查状态与可达性。
12. 打开「页面流程」「需求差异」「讨论问题」，逐条记录选择。

## 讨论问题

1. **整体 IA**：A 双区模块独立 / B 月份工作台 + 配置中心 / C 任务驾驶舱 + 模式，选哪个？是否需要混合（例如 A 的侧边栏 + B 的月份 stepper）？
2. **配置边界**：六类配置是否都应独立成页？「字段与公式」与「计算方案」的边界是否清楚，还是应该合并？全局参数放配置区还是系统设置？
3. **月度主入口**：默认落地应是工资列表、月份工作台还是驾驶舱？「核算与确认」是否值得独立成页，还是放进工资列表的月份状态条？
4. **月份上下文**：月份应放在顶栏全局切换还是只在月度页内？切换配置页再回来是否保留月份？B 的 stepper 是否比 A 的月份条更清楚？
5. **公式编辑器**：字段 / 函数 / 参数面板 + 实时试算是否足够？试算样例用真实员工还是合成样例？保存时阻断错误 vs 允许保存草稿？
6. **导入预览**：来源分色（考勤 / 文件 / 手工 / 清零 / 错误）是否可读？错误行是阻断提交，还是「仅保留有效行」？缺失员工按 0 清零是否需要在提交前二次确认？
7. **工资列表**：默认列是否合适？成本中心（含下级）筛选放在列表还是成本报表？明细抽屉的分区（字段 / 考勤 / 快照 / 校验）是否过重？
8. **工资条与导出**：正式 / 预览的呈现是否足够区分？批量导出放在工资条页还是独立「导出任务」页？导出任务表是否需要常驻？
9. **成本统计**：树表 + 下钻 + 三态预算是否满足？「未分配」与公司合计的呈现是否清楚？是否需要在工资列表与成本报表之间提供更强的互链？
10. **状态与异常**：当前覆盖加载 / 空 / 错误、考勤过期、未锁定、范围变化、未装配、失败批次、配置已更新；还缺哪些真实状态（例如并发导入、导出失败、负数实发）？

## 与需求原型的差异

需求原型（`docs/requirement/rx-hr-prototype.html`）的薪资面板是一个顶部页签 + 纵向长页：工资列表、计算方案、薪资构成、工作日/考勤、岗位档案、考勤管理、月度导入、字段/公式、参数设置依次堆叠；导航把考勤、薪资、权限与员工端混在同一层。本原型在以下方面明确不同：

| 维度 | 需求原型 | 本原型 | 为什么 |
|---|---|---|---|
| 导航 | 顶部页签 + 纵向长页堆叠；考勤与薪资混在同一面板 | 薪资独立模块；配置（低频、公司级）与月度工作（每月、按公司 + 月份）分离 | 两种工作节奏不同：配置需要横向比较与版本，月度工作需要月份上下文与状态机 |
| 配置结构 | 构成 / 方案 / 工作日 / 岗位 / 字段 / 参数分散在同一长页 | 配置区独立：薪资构成、计算方案、工作日参数、岗位装配、字段与公式、全局参数 | 配置一次、复用多岗位；不应被月度操作打断 |
| 月度状态 | 工资列表 + 发布工资条按钮；没有核算批次与状态门 | draft → calculated → confirmed → paid；确认 / 发放需检查考勤、输入版本与范围 | 把「能算」「可确认」「已发放」分开，避免静默改数 |
| 月度导入 | 文本域 + 解析 + 确认导入；列映射与错误报告较弱 | 批次向导：上传 / 粘贴 → 列映射 → 预览校验 → 提交；来源分色、错误行、清零、覆盖手工值 | 导入应可审计、可回退；考勤列只识别不生效 |
| 公式编辑 | 字段表 + 文本公式；缺少插入与实时试算 | 字段 / 函数 / 参数插入、实时试算、错误诊断、依赖拓扑序、修订记录 | 业务人员自助配置需要低门槛与可解释错误 |
| 工资列表 | 一张宽表 + 点击看字段明细 | 动态列 / 部门（含下级）/ 岗位 / 成本中心（含下级）/ 未分配筛选 / 合计 / 明细抽屉 | 列表回答「谁拿了多少」，抽屉回答「为什么是这个数」 |
| 工资条 | 发布到员工端 H5；未区分正式 / 预览与快照 | 正式（最新已发快照）/ 预览（当前成功批次）分离；异步 ZIP / 合并 PDF / Excel；24h 产物 | 发放凭证必须可复现；员工端 H5 在本 effort 之外 |
| 成本统计 | 成本架构面板内联统计 + 预算 | 独立月度报表；冻结成本中心全路径（含下级）、未分配单列、三态预警、下钻到人 | 组织调整不应改写历史；预算口径与部门汇总并列 |
| 权限 | RBAC + 部门数据范围过滤 | 本期沿用登录；所有登录用户拥有薪资全部权限；API 预留 `payroll_access` | RBAC 是另一个 effort；不要让原型暗示未实现的能力 |
| 状态与异常 | 主要覆盖正常路径 | 加载 / 空 / 错误；考勤过期 / 未锁定 / 范围变化 / 未装配 / 失败批次 / 配置已更新 | 异常状态是薪资月的一等公民，不是补丁 |

核心 IA 改进是：**配置与月度不是同一个工作面的两段，而是两种节奏**。配置是低频、公司级、需要版本与横向比较；月度是高频、按月份、需要状态机、批次与异常。把它们塞进同一长页会让每个任务都妥协。

## 样本数据

## 已知限制

- 刷新即重置；没有持久化、真实鉴权或 RBAC。所有登录用户拥有薪资全部权限，与本期决议一致。
- 公式求值器是界面演示用简化版：使用 JS `Number` 而不是 Decimal，未执行 ADR-0007 的全部安全限额（字符 / token / 深度 / 步数），金额精度校验只覆盖常见情况；**黄金用例仍是计算契约**。
- 导入向导解析的是简单逗号分隔文本，不支持引号、换行、编码与真实 Excel；不保留原始文件字节。预览批次 24 小时过期只做文案展示。
- 批量导出与单张 PDF 不生成真实字节；异步任务用定时器模拟进度，未实现 worker、共享卷、410 / TTL 的实际行为。导出审计为内存行。
- 历史月重算在原型中仍按当前配置求值，只展示「历史月沿用快照」的分类与提示；未实现按最近成功批次快照回放。历史月配置更正属于后续 effort。
- 成本报表未渲染「已删除成本中心的冻结幽灵行」；当前样本只覆盖启用中的成本中心。多月份趋势、人均成本、成本报表导出均不在本期。
- 预算 / 预警线只读（基础管理维护）；原型不提供预算编辑或月度预算历史。
- 手工录入只保留最后写入者；没有字段级审计。负数实发、并发导入、导出失败等状态未内置样例（可在讨论问题中决定是否补）。
- 考勤模块以只读来源呈现；原型不实现考勤月结、解锁或汇总同步，只模拟「考勤过期 / 未锁定」状态。
- 只内置 2026-10 / 11 / 12 三个月；荣新物流为空数据。弹层有初始焦点、Esc 关闭与 `aria-modal`，但未实现完整焦点陷阱；可达性按「可评审」标准，而非 WCAG 全量审计。
